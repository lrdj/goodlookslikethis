## Design Specificity Verdict

**LLM assessment**: This is a competently built, on-system blog index — the ledger grid, the gold hover reveal, the flat bordered surfaces all match `DESIGN.md`'s "Annotated White Paper" system precisely. But the page itself could be almost any personal blog's homepage. Nothing in the first viewport signals *this specific product*: a GOV.UK-fluent consultant with named public-sector clients, selling credibility to ministers and senior civil servants. The `<h1>` is the self-deprecating tagline "Some of Dug's slightly more interesting design things…" — the site's actual name ("Good looks like this") and Dug's identity never appear as visible text on this page, only inside an image `alt` attribute in the header logo and the `<title>` tag. PRODUCT.md's Product Principle 1 is "show the work" and Principle 2 is "every case earns a conversation" — this page shows a blog roll, not the case studies that carry the named-client evidence, and it closes with a "Load more" pagination link rather than any invitation to get in touch. The component craft is specific to the system; the page-level composition and messaging are not specific to the product.

## Overall Impression

The component-level craft is genuinely good — the site's own design system (gold marginalia, flat ledger grid, the hover-flood signature move) is followed faithfully. But the homepage, as the site's front door, reads as a content list before it reads as a credibility statement. For an audience that includes ministers and senior civil servants deciding whether to trust a supplier, the biggest opportunity is closing the gap between "this is a nicely built blog" and "this is evidence I should hire this person" — right now that case only starts once a visitor clicks into a post.

## What's Working

- **The index-tile hover reveal** (gold flood, greyscaled image fade-in, inverted text) is a genuine signature moment — restrained until touched, exactly as `DESIGN.md`'s "one moment of theatre" doctrine describes it, and it's the one place the page feels authored rather than templated.
- **The ledger grid** (hairline borders, first-item span-2, disciplined 66%-adjacent padding) gives the article list real structure without any decoration doing the work — borders and fills carrying hierarchy is exactly the "flat by doctrine" system in practice.
- **Front-matter fallbacks are handled cleanly** — `index_image` falling back to `hero_image`, `blogIndexSubtitles` falling back from `post.subtitle` to a truncated excerpt — this is quietly good engineering that keeps 41+ posts of messy, migrated content rendering without visible breakage.

## Priority Issues

- **[P1] The homepage carries no identity, positioning, or contact CTA**: What: the first viewport is a self-deprecating tagline followed immediately by a content grid; there is no line establishing who Dug is, what he does, or why a public-sector buyer should trust him, and the page ends on "Load more" with no invitation to get in touch. Why it matters: PRODUCT.md states success for a visit is that it "starts a conversation," and this is the site's root URL — the front door for recruiters, search visitors, and anyone not arriving via a tailored case-collection link. A cold visitor gets zero positioning before they're asked to start reading. Fix: add a short identity/positioning line above the article list (name, GOV.UK-fluency signal, scope of work) and consider a contact prompt near the pagination controls, mirroring the CTA that already closes every case study. Suggested command: `/impeccable shape`

- **[P1] The signature hover interaction is invisible to keyboard and touch users**: What: `.article-list article:hover` (and its `figure::before` counterpart) is the only trigger in `posts-index.css` for the gold flood and image reveal — there is no `:focus-within` or `:focus-visible` equivalent. Why it matters: PRODUCT.md sets WCAG AAA as the target and AA as the floor; keyboard-only and screen-reader users (persona Sam) tab to the same link but never get the visual confirmation sighted mouse users get, and touch users (persona Casey — the likely majority on a shared mobile link) never see it at all since touch has no true `:hover`. The site's one moment of visual delight is desktop-mouse-only by default. Fix: add `article:focus-within` rules mirroring the `:hover` block. Suggested command: `/impeccable adapt`

- **[P2] The visible `<h1>` is not the site's identity**: What: `h1#headTitle` renders `page.subtitle` — "Some of Dug's slightly more interesting design things…" — while the actual brand name and Dug's name never appear as page text, only inside the header logo's `alt` attribute and the `<title>` tag. Why it matters: for a first-time visitor (persona Jordan — a civil servant clicking a cold link) and for search engines, the page's most prominent text doesn't identify the site or its author. Fix: either promote the identity into visible copy near the H1, or accept the tagline as intentional voice but pair it with a visible byline. Suggested command: `/impeccable clarify`

- **[P2] "(comments disabled)" repeats on every index tile**: What: `<span id="postComments"><i>(comments disabled)</i></span>` renders unconditionally on all 41+ posts across every paginated page. Why it matters: it's extraneous cognitive load that tells visitors about an absent feature rather than simply omitting it — small but repeated friction that undercuts the "serious, measured" tone PRODUCT.md asks for. Fix: remove it from the index view. Suggested command: `/impeccable distill`

- **[P3] A dead GOV.UK Frontend utility class ships on the readit audio player**: What: the `<audio>` element for `readit` posts carries `class="govuk-!-margin-bottom-3"`, but no GOV.UK Frontend CSS is ever loaded (confirmed in `_includes/2023/head.html` — only the site's own three stylesheets are linked), so the class does nothing. Why it matters: this audience includes people who know GOV.UK Frontend by sight; a dead reference to it reads as copy-paste residue rather than "the build is the argument," which PRODUCT.md names as a brand commitment. Fix: remove the dead class or replace it with a real spacing rule from the site's own system. Suggested command: `/impeccable audit`

## Persona Red Flags

**Jordan (Confused First-Timer — here, a civil servant opening a cold link)**: Lands on a page whose only visible text is a self-deprecating tagline; nothing tells Jordan who Dug is, that he's worked on HMRC/Defra/Irish DSP engagements, or where the case studies live beyond an unlabelled icon in the header (`nav-cases-box.svg`, text only in `alt`). Jordan has to click through at least one post before getting any sense of credibility — high risk of bouncing before that click.

**Sam (Accessibility-Dependent User — WCAG AAA is the site's own stated target)**: No skip-to-content link exists anywhere in the 2023 template family, so Sam tabs through the full header before reaching the article list on every visit. The signature hover reveal never fires on keyboard focus. Several sampled posts (e.g. `the-first-100-d-1.html`, `2025-10-10-what-facilitators-know.md`) ship `hero_image_alt: ""`, so the `<figure>` background-image tile — the visual evidence this portfolio's whole positioning rests on — has no accessible content for Sam on those tiles at all.

**Casey (Distracted Mobile User)**: The gold-flood/image-reveal interaction is hover-only, so on a phone — the likely device for someone opening a shared link on the go — Casey never sees it; the tiles read as flat text blocks with no visual reward. Functionally fine, but the one piece of personality the homepage has is invisible to her.

## Minor Observations

- No publish date is shown anywhere on the index (`postPubDate` is commented out in `2023/post.html` too — a site-wide choice, not a bug), which costs a credibility-focused audience the ability to judge how current the thought leadership is.
- Header nav (`about`, `blog`, `cases`) is icon-only with no visible text label — only `alt` text, which sighted users never see.
- `_posts/exchange-arabic.md` has malformed front matter (opens with `<--` instead of `---`), so Jekyll never parses it as a post — it doesn't reach the index, but it does get copied as orphaned static content into `/NOT_cases/` and `/cases/2011-...` in the build output. It sits in the live `_posts/` directory rather than one of the documented backlog folders, so it isn't flagged by the existing "known issues" list in CLAUDE.md.
